# Reusable audit release v3

Version: **3.0.0**. Date: 10 October 2026.
Implementer: Codex. Independent reviewer: Claude, review deferred.

The owner requested one updated reusable release. The result is one clean,
hash-manifested package in `audit_template/framework/v3/`: **159 framework files**
and six company setup records generated by the installer.

## What changed and why

- Current documentary reports show the stored scores and supporting/contrary
  arguments. They do not replace a result with a judgment-entry form.
- The matching package, dashboard and evidence-bundle stack keeps exact quotes,
  full chapters and traceable links. Portable review folders preserve report mode.
- Light and separate dark presentations use the same company data. The dark skin
  includes background lighting, a faint grid and a decorative cursor spotlight.
  Printing remains light. No audit calculation runs in the browser.
- First-release publication pins exact bytes, refuses overwrites, restores normal
  Windows destination permissions and records a release marker. Temporary aliases
  are removed before validation, so the existing hard-link rejection stays strict.
- Baseline and 1 MiB capacity profiles are included as local candidates. The larger
  profile requires that company's signed fingerprint-bound approval, not Enconet's.
- Fresh source registration preserves incoming, reset remains preview-first and
  approval-controlled, and optional source-stated crumb anchors are stored/validated.
- Shared integration defects found by tests were fixed once in the template:
  matching schemas/templates and dependencies, Unicode supplier display names,
  UTF-8 console output, inline gate state, validator flags and generation tooling.

## Clean boundaries

No vendor or regulatory source text, database, crumb, evaluation, finding,
published output, source edition, owner decision, active prompt, company golden
fixture or no-backup waiver is copied. Common Appendix B criterion names and
general extraction concepts remain framework material.

Approvals are header-only. Prompt activation is empty. Source-code selection
starts empty. Scoring calibration and source/supplier scope remain local owner
decisions. Registered authority/source codes are not approved editions.
Claude guidance, skills and records are not created or changed by Codex.

Build-time provenance may name the source projects. Installed runtime resolves
its own local root and never imports sibling code or reads sibling audit data.
Sharing a configured Python/browser runtime is allowed; sharing audit data is not.
