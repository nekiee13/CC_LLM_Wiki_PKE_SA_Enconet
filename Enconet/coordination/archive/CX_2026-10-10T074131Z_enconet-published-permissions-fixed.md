# Published dashboard access — permission repair

The owner reported `ERR_ACCESS_DENIED` when opening the published dashboard.
The file existed and its hash was correct, but it was not readable to a normal
browser user. This was a publication defect, not a missing document or bad score.

## Cause

The first-release publisher staged files in a private Windows temporary folder.
Hard links kept that folder's restrictive file permissions when installed in
the output folder. All 12 released files and their manifest had protected ACLs
that allowed only Owner Rights, SYSTEM and Administrators. The prior elevated
browser test could read them, which masked normal-user access failure.

## Repair

`scripts/repair_release_permissions.ps1` previewed the exact 13-file set and
verified its hashes. Apply restored each file's normal destination-folder
permission inheritance with `icacls <exact-file> /reset`. It did not recurse,
grant Everyone access, replace files, change content or touch source documents.
Before/after ACLs and hashes are retained in:

- [Before](../out/2026-10-10/release-acl-repair/before.json)
- [After](../out/2026-10-10/release-acl-repair/after.json)

All 13 hashes stayed identical. All 12 payloads and the manifest are now
readable without tool escalation. The dashboard has inherited ordinary
Users read/execute permissions. Its byte hash remains
`bf62a3fe044e488a9659c0d74b03df04f40c519c608bfc5b7da81d792ec633f1`.

[Retry the dashboard](../outputs/enconet_appendix_b_dashboard.html).
Refresh the existing browser tab; the URL has not changed.

## Prevent recurrence

The publisher now restores destination-parent permissions before validating
payloads and also for the result manifest. A permission failure fails closed
and removes only unchanged files created by that transaction, including a
new manifest. No existing approved file is overwritten.

Fifteen focused tests pass. Six new checks cover permission restoration order,
marker-failure rollback, exact-file Windows commands, permission-command
failure, and native publication with two names (spaces and Croatian characters).
Sibling files stay unchanged. The owner-approved release bytes and its
immutable manifest are not regenerated by this repair.
